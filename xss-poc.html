PostMessage XSS PoC - Extension Vulnerabilities

Open this page on a site where the target extension content scripts are injected.
Then click the buttons below to trigger each attack vector.

PoC 1: HARPA AI Bus Message Injection (cs.js)

Vulnerability: cs.js listens for window.postMessage with no origin check. The only validation is _isBusMsg: e.$bus === true && e.appName === "__app_hrp". Any page script can craft this message. The handler calls _callHandlers with attacker-controlled name and args, and relays to the extension background via _sendToExt.

PoC 2: HARPA AI - chrome.runtime.onMessage relay to postMessage("*")

Vulnerability: cs.js relays chrome.runtime messages to the page via window.postMessage(t, "*"). The response message {resId, result} is also posted with "*". An attacker page can listen for these responses to intercept extension internal data.

PoC 3: TextCortex - rrweb Session Replay Data Theft (668.js)

Vulnerability: rrweb in 668.js posts session recording data (full DOM snapshots, mutations, user interactions) via window.parent.postMessage({type:"rrweb",...}, "*"). If the extension page is iframed, the parent steals all session data.

Note: This creates an iframe to a target site. The extension's rrweb will post data to us.

PoC 4: TextCortex - Redux State Exfiltration (popup.js / sidepanel.js)

Vulnerability: popup.js and sidepanel.js broadcast full Redux store state via window.postMessage({body:"Data", state:JSON.stringify(store)}) with no targetOrigin. Any same-page listener captures the entire application state including auth tokens.

PoC 5: TextCortex - rrweb Fake Event Injection (668.js)

Vulnerability: The rrweb handleMessage checks t.data.type === "rrweb" && t.origin === t.data.origin. The origin check is self-referential - the attacker sets data.origin to match their own event.origin. A cross-origin iframe can inject fake rrweb events into the parent's recording pipeline.

PoC 6: HARPA AI - executeJs via DOM event handler (cs.js)

Vulnerability: cs.js has an executeJs method that creates a DOM element, sets onreset attribute with the JS code, and dispatches a reset event. This bypasses CSP in some configurations. If any bus handler path reaches executeJs with attacker-controlled input, it achieves arbitrary code execution.
